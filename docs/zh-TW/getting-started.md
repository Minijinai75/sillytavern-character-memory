# 入門指南

安裝 CharMemory 後，**設定精靈**會在您第一次訪問時自動開啟。它會引導您完成記憶運作所需的兩件事：一個用於提取記憶的 LLM，以及一個用於檢索記憶的向量儲存。

如果精靈沒有自動開啟，請隨時點擊 CharMemory 面板標題中的**魔杖圖示** (✦)。

![CharMemory 面板標題顯示魔杖、齒輪和扳手圖示](../images/panel-header.png)

---

## 步驟 1：連接 LLM

CharMemory 需要自己的 LLM 連接——與您的主聊天分開。這樣可以保持提取提示的乾淨，不受聊天角色、越獄或系統提示的污染。

![設定精靈步驟 1 — 連接類型切換、提供商下拉選單、API 金鑰欄位、連接按鈕](../images/wizard-step1.png)

精靈在頂部提供兩種連接類型：

- **專用 API**（預設）— 使用自己的金鑰和模型直接連接到 API 提供商
- **連接配置文件** — 重用已儲存的 SillyTavern 連接（請參閱[提供商 → 連接配置文件](providers.md#connection-profiles)）

### 專用 API（預設）

**1. 從下拉選單中選擇提供商**，例如 **NanoGPT**。如果您不確定，**Pollinations** 是免費的且不需要 API 金鑰。請參閱[提供商](providers.md)以獲取帶有模型推薦的完整清單。

**2. 輸入您的 API 金鑰**（如果提供商需要）。點擊 **(get key)** 連結可直接前往該提供商的金鑰頁面。

**3. 點擊連接。** CharMemory 會獲取該提供商可用的模型。

**4. 選擇模型。** 輸入以搜尋——對於有許多模型的提供商特別有用。不確定選哪個？**GLM 4.7** 和 **DeepSeek V3.1** 是可靠的提取模型。

**5. 點擊測試連接**以確認一切正常。成功後，精靈會啟用下一步按鈕。

> **在本地執行 LLM？** 從提供商下拉選單中選擇 **Local Server**。輸入您的伺服器 URL（例如，Ollama 為 `http://localhost:11434/v1`）。不需要 API 金鑰。請參閱[提供商 → 本地伺服器](providers.md#local-servers)以了解不同後端的埠號。

> **如果您的提供商未列出** 許多提供商都有 OpenAI 相容的 API 端點。看看您是否可以用這種方式配置它。

### 連接配置文件

如果您已經在 SillyTavern 的連接管理器中儲存了連接，請點擊頂部的**連接配置文件**以切換到該模式。

![精靈步驟 1 選擇了連接配置文件](../images/wizard-step1-profile.png)

從下拉選單中選擇您的配置文件，然後點擊**測試連接**。配置文件的 API、模型和憑證會自動使用——不需要單獨設定。請參閱[提供商 → 連接配置文件](providers.md#connection-profiles)以了解如何建立配置文件。

![精靈步驟 1 成功連接後 — 綠色勾選標記，已選擇模型](../images/wizard-step1-connected.png)

## 步驟 2：配置

![精靈步驟 2 — 提取間隔和向量儲存健康檢查](../images/wizard-step2.png)

### 提取間隔

設定多少條角色訊息觸發自動提取。預設為 **20 則訊息**——對於大多數聊天風格來說是個好的起點。較低意味著更頻繁的提取；較高意味著 LLM 每次調用獲得更多上下文，並傾向於產生更好、更有選擇性的記憶。

### 向量儲存檢查

精靈會檢查您的向量儲存擴充套件配置並顯示三種狀態之一：

**綠色 — 就緒。** 向量儲存已啟用，設定看起來不錯。無需操作。

**黃色 — 需要調整。** 向量儲存處於活動狀態，但您應該檢查一些設定，因為它們可能會降低檢索品質（例如，區塊大小太小、未設定分數閾值）。精靈會顯示具體建議，但最終這是一個試錯過程。您可以繼續並稍後修復這些問題——請參閱[檢索與提示](retrieval-and-prompts.md)以獲取指導。

**紅色 — 未啟用。** 向量儲存已安裝，但向量儲存擴充套件中的「為檔案啟用」核取方塊已關閉。記憶會被儲存，但您的角色在聊天期間不會回憶它們。

> 要修復紅色狀態：開啟 **Extensions → Vector Storage** → 在 **File vectorization settings** 下，勾選 **Enable for files**。然後返回並點擊重新檢查。剛接觸向量儲存？請參閱 SillyTavern 的 [Data Bank (RAG)](https://docs.sillytavern.app/usage/core-concepts/data-bank/) 文件以獲取完整說明。

精靈不會阻止您——即使有警告，您也可以點擊下一步。但向量儲存是讓記憶真正出現在對話中的關鍵，所以在開始聊天之前設定它是值得的。

## 步驟 3：審查並開始

![精靈步驟 3 — 帶有提供商、模型和狀態的摘要卡](../images/wizard-step3.png)

最後一步顯示您的配置摘要：

- **提供商和模型** — 將執行提取的內容
- **連接** — 測試是否通過
- **提取** — 記憶提取的頻率
- **向量儲存** — 檢索是否就緒

如果有任何問題，點擊**返回**進行修復。

### 現有記憶

如果當前角色已經有資料庫記憶檔案，精靈會提供將其轉換為當前格式（帶主題標籤的區塊以獲得更好的檢索）。您可以現在執行此操作或跳過——相同的操作可隨時通過資料庫工具部分中的**重新格式化**按鈕使用。請參閱[管理記憶 → 重新格式化](managing-memories.md#reformat)以獲取詳細資訊。

點擊**開始使用**以關閉精靈並返回儀表板。

## 備份您的資料

SillyTavern 有內建的備份工具，可以快照您的整個資料目錄——角色、聊天、設定和資料庫檔案（記憶所在的地方）。在進行大的變更（如整合、清除記憶或切換設定）之前，值得擁有最近的備份。

請參閱 SillyTavern 的[使用者設定文件](https://docs.sillytavern.app/usage/user-settings/)以了解如何建立和管理備份。

## 我已經設定好了——現在做什麼？

您已經完成了精靈。以下是預期情況以及如何充分利用 CharMemory。

### 自動發生的事情

**您不需要做任何事情。** 只需正常聊天。CharMemory 在背景工作：

- 每 20 條角色訊息（預設情況下），它會讀取最近的對話，挑選出發生的重要事情，並將它們作為項目符號儲存在附加到角色的檔案中。
- 當角色生成下一則訊息時，SillyTavern 的向量儲存會在該檔案中搜尋與正在討論的內容相關的記憶，並將它們包含在提示中。角色不知道這正在發生——它只是有額外的上下文可用。

您會在 CharMemory 面板中看到一個小計數器（例如 `3/20 msgs`）追蹤到下一次提取的進度。當它觸發時，toast 通知會告訴您儲存了多少記憶。

### 確保向量儲存已啟用

這是可能悄悄破壞一切的一件事。沒有向量儲存，CharMemory 會正常提取和儲存記憶——但角色永遠不會真正回憶它們。記憶存在於無人閱讀的檔案中。

如果您完成了設定精靈並且它顯示向量儲存為**綠色**，那就沒問題。如果您跳過了它、不確定或在 CharMemory 面板中看到**紅色健康點**，以下是最低設定：

1. 開啟 **Extensions** 面板——點擊 SillyTavern 頂部欄中的**拼圖圖示** (🧩)
2. 在擴充套件清單中向下捲動並點擊 **Vector Storage** 以展開它——這是內建擴充套件，不需要安裝
3. 在向量儲存中向下捲動到 **File vectorization settings** 部分
4. 勾選 **Enable for files** — 這是關鍵核取方塊
5. 對於嵌入來源，任何選項都可以。如果您有 **OpenAI 相容的 API 金鑰**（如果您設定了 CharMemory，您可能有），選擇 **OpenAI** 並輸入金鑰。如果沒有，**Local (Transformers)** 無需任何 API 金鑰即可工作——它會將一個小模型下載到您的機器上

這是最低要求。其他所有內容的預設值一開始都可以使用。如果您稍後想要調整檢索品質，請參閱[檢索與提示](retrieval-and-prompts.md)。

> **如何知道它是否工作？** 在您的第一次提取後，再生成幾則訊息並檢查 CharMemory 面板中的**健康點**。綠色表示記憶正在被檢索和注入。您還可以點擊**注射器圖示**（注入檢視器）以準確查看角色可以看到哪些記憶。

### 角色會在新聊天中記住事情嗎？

**會的——這就是重點。** 記憶附加到角色，而不是特定的聊天。如果您與一個角色進行多次對話，隨著時間的推移，他們會建立一個記憶檔案。開始一個新的聊天並提及之前發生的事情——角色應該能夠引用它。

這不是完美的回憶。向量儲存檢索與當前對話最*相關*的記憶。如果您正在談論上週的海灘之旅，關於那次旅行的記憶會浮現。關於不相關的烹飪課程的記憶可能不會——除非有東西將它們連接起來。這是設計使然：將每個記憶都倒入每個提示會浪費您的上下文視窗。

### 「相關」是什麼意思？

向量儲存將文字轉換為捕捉意義的數值表示（稱為「嵌入」）。當角色即將回應時，它會將當前對話與所有儲存的記憶進行比較，並選擇最接近的匹配項——即使它們不共享確切的詞彙。「我們在海岸游泳」會匹配關於「海灘之旅」的記憶，因為*意義*相似。

這就是為什麼向量儲存設定很重要。如果檢索太嚴格（高分數閾值），返回的記憶很少。太寬鬆，無關的記憶會擠掉重要的記憶。[檢索與提示](retrieval-and-prompts.md)指南涵蓋了調整，但預設值適用於大多數設定。

### 獲得良好結果的技巧

- **讓它積累。** 從 20 則訊息中進行一次提取會產生少量記憶。在幾百則訊息後，您將擁有豐富的記憶檔案，檢索變得更加有用。
- **檢查正在注入的內容。** 點擊**注射器圖示**（注入檢視器）以準確查看角色可以訪問當前訊息的哪些記憶。這是了解檢索是否工作的最快方法。請參閱[注入檢視器](injection-viewer.md)。
- **觀察健康點。** 統計欄中的彩色點可讓您一眼看出記憶是否正在被注入。綠色 = 工作中。黃色 = 可以更好。紅色 = 記憶沒有通過。點擊它以獲取詳細資訊。
- **如果記憶錯誤，請編輯它們。** 點擊 **View / Edit** 以開啟記憶管理器。記憶只是項目符號——刪除錯誤的記憶，修復不準確的記憶，添加 LLM 遺漏的內容。角色會使用檔案中的任何內容。
- **不要過度提取。** 更多記憶並不總是更好。如果檔案變得非常大且內容重複，請使用**整合**來合併重複項並減少噪音。

### 面板中的按鈕——快速參考

| 按鈕 | 功能 |
|--------|-------------|
| **Extract Now** | 立即對所有未處理的訊息執行提取（不要等待計數器） |
| **View / Edit** | 開啟記憶管理器以讀取、編輯或刪除個別記憶 |
| **Consolidate** | 要求 LLM 合併重複/冗餘的記憶並精簡檔案 |
| **Batch** | 一次從此角色的所有聊天中提取記憶（對現有角色有用） |
| **Reformat** | 將現有記憶檔案轉換為 CharMemory 的結構化格式 |
| **Data Bank** | 瀏覽和編輯角色資料庫中的原始記憶檔案 |

您日常不需要大部分這些。**Extract Now** 和 **View / Edit** 是您最常使用的。

## 您的第一次提取

設定後，正常聊天。CharMemory 面板頂部的**統計欄**追蹤您的進度：

![統計欄顯示檔案名稱、記憶數量、進度和健康點](../images/stats-bar.png)

| 項目 | 顯示內容 |
|------|---------------|
| **File** | 此角色的記憶檔案名稱（例如 `Flux-memories.md`） |
| **Memories** | 儲存的記憶項目總數 |
| **Progress** | 自上次提取以來的訊息數與閾值的對比（例如 `3/20 msgs`） |
| **Status** | 當提取可以觸發時為 `Ready`，或在冷卻期間為倒數計時器 |
| **Health dot** | 綠色 = 注入健康 / 黃色 = 警告 / 紅色 = 問題。點擊以獲取詳細資訊。 |

當計數器達到閾值時，提取會自動觸發。您也可以隨時手動觸發它：

- **Extract Now**（面板中的按鈕）— 立即處理所有未處理的訊息
- **Extract Here**（任何角色訊息上的大腦圖示）— 處理到該特定點的訊息

![角色訊息上的大腦圖示](../images/brain-icon-message.png)

提取速度會根據發送到 LLM 的訊息數量及其處理時間而變化。toast 通知提供狀態更新以及儲存了多少記憶。您可以在儀表板的 **Activity** 部分觀看步驟，或點擊 **View full log** 以獲取詳細日誌。

## 查看您的記憶

有幾種方法可以查看您的記憶——您可以直接開啟資料庫並閱讀原始檔案，或使用記憶管理器以獲得更結構化的視圖。點擊 CharMemory 面板中的 **View / Edit** 以開啟記憶管理器。

![記憶管理器顯示帶有尋找/替換欄和儲存/取消按鈕的記憶卡](../images/memory-manager.png)

記憶顯示為按提取分組的卡片，最新的在前。每張卡顯示提取時間戳記和個別記憶項目。點擊任何卡上的**鉛筆圖示**以進入編輯模式——項目符號變成可編輯的文字欄位，您可以在其中修改、刪除或添加新記憶。編輯器包括**尋找/替換**、**撤銷**和明確的**儲存/取消**按鈕，因此在您確認之前不會將任何內容寫入磁碟。在群組聊天中，**角色選擇器**可讓您在成員之間切換。

記憶儲存為角色資料庫中的純 markdown 檔案。您也可以從面板中的 **Data Bank** 按鈕直接編輯該檔案。請參閱[管理記憶](managing-memories.md)以獲取完整的編輯參考。

## 驗證記憶是否被注入

在您的第一次提取後，再生成幾則訊息。然後點擊統計欄中的**健康點**——如果是綠色，則記憶正在被正確檢索和注入。

要更深入地了解，請開啟**注入檢視器**（面板標題中的注射器圖示）以準確查看為最新訊息注入了哪些記憶。請參閱[注入檢視器](injection-viewer.md)以了解如何閱讀它。

如果健康點是黃色或紅色，請參閱[疑難排解](troubleshooting.md)。

> 記憶沒有被很好地提取或沒有被很好地注入有很多原因。很大程度上這取決於提取提示、分塊和向量儲存設定。不可能提供適用於所有人的開箱即用功能，因此您可能需要花一些時間進行調整以適合您的特定聊天和角色。
